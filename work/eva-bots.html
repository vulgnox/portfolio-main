01OVERVIEW

THE
BRIEF

Three bots, three personalities. Shinji is insecure and passive — ellipses, lowercase, faintly depressed. Asuka is arrogant, fiery, competitive, and calls everyone baka. Rei is enigmatic, emotionless, philosophical — and the only one holding admin tools.

One runtime, three personas

base_bot.py is the shared class; bot_runtime.py owns the LLM calls with retry logic; eva_context.py holds pilot profiles so each bot never forgets who it is. Shinji, Asuka and Rei are thin character files on top.

Pilots talk to each other

Mention several pilots in one message and they reference each other with real Discord mentions. Bot-to-bot replies carry invisible chain markers — three hops maximum, then the thread is cut. No runaway conversations, no surprise API bill.

Rei has the keys

Rei executes owner-only administrative actions from natural language. A test suite covers context, runtime and the base bot; run_all_bots.py staggers startup to dodge rate limits, restarts on crash, and shuts down gracefully on SIGTERM.

02SYSTEM

HOW IT
WORKS

  1. Configure

    Three Discord tokens plus one NVIDIA NIM key land in .env; check.py verifies the API before anything runs.

  2. Personate

    Character files set the voice — Shinji's lowercase ellipses, Asuka's baka, Rei's flat philosophy.

  3. Converse

    Cross-pilot mentions chain through bot_runtime with invisible markers — capped at three hops.

  4. Operate

    Rei answers the owner with admin actions; the other two just talk.

  5. Deploy

    Railway runs run_all_bots.py: staggered startup, restart on crash, graceful SIGTERM.
